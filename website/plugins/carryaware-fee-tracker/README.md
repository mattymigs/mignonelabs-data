# CarryAwareNJ Municipal Fee Tracker

Review-only package. Not installed on mignonelabs.com. It adds its own shortcode and assets without replacing the active Mignone Labs Site plugin, theme, or Core snippets.

The production shortcode reads `https://mattymigs.github.io/carryaware-data/nj_carry_fee_relief.json`. No municipality dataset is included inside the installable plugin. The website displays the feed's review dates; a failed production request can use a clearly labeled browser-session snapshot. With no valid snapshot it shows an unavailable message and no misleading zero totals. The private preview does not fetch or use browser storage.

After approval to install and create an authenticated draft: install/activate this plugin (public mode defaults off), then open Tools → CarryAwareNJ Fee Tracker. Paste the unchanged review `nj_carry_fee_relief.json` into **Private preview snapshot**, leave public mode disabled, and save. The Settings API checks the nonce and `manage_options`; malformed/oversized JSON is rejected without replacing a saved valid snapshot. The new option is created without autoload and is not REST-exposed. It is stored in the WordPress database, never as a publicly reachable JSON file.

Create or reuse a **draft** page titled “New Jersey Municipal Carry-Permit Fee Tracker” with slug `nj-carry-permit-fee-refunds`, use the existing `page-no-title` template, and insert `[carryaware_fee_tracker]` in a Shortcode block. Preview while signed in as an administrator. The banner must say **PRIVATE PREVIEW — saved snapshot; no live updates**. No production data merge is needed. A page with another slug also receives cache protection. WordPress must prevent anonymous draft access; noindex alone is not access control. Inspect the signed-in live-theme preview and anonymous denial before publication.

The snapshot is sent only when the viewer has `manage_options` and the currently queried page is draft, pending, or private. Published pages always use the fixed production feed, even with `?preview=true` or a saved snapshot. A missing or invalid private snapshot fails closed without a production fetch. Inline JSON uses `wp_json_encode` with all four `JSON_HEX_*` flags; DOM text is populated via textContent. Private previews neither read nor write sessionStorage. Cache headers and LiteSpeed no-cache hooks protect canonical pages, shortcode pages, and page previews; confirm the site's actual cache honors these controls.

Publishing the dataset, enabling public mode, publishing the page, and sending an app notification are separate release actions; none has been performed by this package. Leave the iOS review branch unmerged. Clear the snapshot by emptying its field and saving; deactivation also deletes it and resets public mode. Only after final approval enable public mode and publish the page.

The local preview harness renders these exact assets against the review checkout's JSON. It is bound to 127.0.0.1 and never writes to WordPress. Browser rendering tests are independent of WordPress integration; a signed-in preview on the live theme is still a release check.

Rollback: change the page back to draft, disable public mode or deactivate the plugin, and purge the page cache. Deactivation resets public mode. No legal alert feed or Firebase notification is changed by this plugin.

Public labels use “Reported full/substantial relief” and “Evidence last reviewed” to distinguish attributed reporting from municipal verification. Legacy JSON status and date keys remain unchanged for compatibility. Point Pleasant remains pending documents.

Compatibility: PHP 8.0+ (`str_starts_with`) and WordPress 6.5+ (`wp_enqueue_script_module`). Integrated checks live in `website/fee-tracker-tests/`; they read the canonical dataset through `CARRY_FEE_DATA_PATH`, without copying it into this repository or plugin. R2 integration adds a refund/remaining-cost consistency check in both PHP and JavaScript. Native Mac PHP passed 44 plugin assertions, JavaScript passed eight model tests, and Playwright passed 17 private-preview plus 11 public/alert regression checks. These check plugin decisions and local assets, not WordPress core authentication or the live theme/cache. See `website/fee-tracker-tests/README.md` for repeatable commands and remaining integration checks.
